# 学习路线覆盖与代码复用评估

日期：2026-10-09。依据：Agent 最速学习路线.md、code/agent_demo.py、agent_core 主要模块及测试定义的静态阅读。本轮未运行测试、未调用模型服务；不将已有测试文件等同于已验证通过。

## 判断

博客助手的管理模式与问答模式可作为全部 12 个主题及补充 RAG 的实践载体。产品功能、学习实验和成熟项目源码阅读分别验收；实现博客助手不等于已经掌握所有章节。路线本身要求优先状态、缓存、推理、恢复和评测，MCP/Skills/Hooks/复杂团队按需。

## 覆盖矩阵

| 主题 | 项目落点 | 验收证据 |
| --- | --- | --- |
| Agent 主循环 | 搜索文章、选工具、读取、回复或提交建议 | 一条端到端执行链及退出条件说明 |
| Function Calling | search_posts/read_post/prepare_changes 等拟议工具 | 参数校验、调用标识与结果配对，错误参数案例 |
| MCP | 保留现有 Skill MCP，按需把博客只读工具暴露为 MCP | 连接/发现/调用/断连记录，不必为覆盖主题额外包装所有函数 |
| State/Context | 会话与批次状态、逐篇恢复、检索上下文、压缩 | 第 3 篇中断后恢复，前两篇不重做；区分 state 与 context |
| Skills | 按需加载文章整理或翻译流程 | 记录选用版本、输入与产物；下载收藏不算流程应用 |
| Prompt Cache | 固定系统提示与工具前缀、比较压缩策略 | 实际 provider usage、缓存 token、时延与成本，多次对照；缺失数据标为未知 |
| Reasoning | 同一模型上比较其实际支持的强度 | 固定任务与质量标准，比较质量/耗时/成本；保存推理项不等于保存完整内部思维链 |
| Hooks | 工具前权限检查、执行后指标、审批等待与恢复 | 正常/失败/超时事件记录；权限 hook 失败应阻断相关操作 |
| 权限/隔离 | 管理模式写操作与只读问答分离 | 读者访问草稿被拒、拒绝审批不发布、正文诱导发布不生效 |
| 错误恢复 | 限流退避、无效输出修正、发布结果核对 | 有限次数/时间预算；发布成功但响应丢失后不重复创建 |
| 子 Agent | 可选独立的译文审校或引用核查子任务 | 独立上下文、产物、父任务校验、超时处理；与单 Agent 比较，按需启用 |
| Trace/评测 | 两种模式共用事件记录和固定用例 | 改动前后同任务集比较；失败归因与回归案例 |
| RAG 补充 | 用户问答先固定检索，再实验自主补查 | 有答案/无答案/多文综合用例，分别检查检索、上下文、回答和引用 |

源码阅读路线 Learn CC → MiniCode → Pi → Codex/OpenCode 仍需单独做专题对照。每次记录本项目机制、参考项目的具体函数/状态、设计差异，以及是否值得引入。

## 代码复用

agent_demo.py 是入口及兼容导出层，核心在 agent_core；建议继续 Python，保留原 CLI 作调试入口。

- 高复用：state.py 的原子写入；mcp_connection.py 的连接适配；reasoning.py 的配置与推理项记录（具体 provider 支持另验）；已有恢复/压缩/错误处理测试的设计和 fixtures。
- 改造后复用：conversation.py 的轮次/循环/保存时机；runner.py 的待执行工具恢复；context.py 的压缩/历史重读；conversation_state.py 的校验迁移；mcp_tools.py 的工具发现与分发。
- 作为可选能力或开发入口保留：skill_library.py、cli.py、presentation.py。Skill 收藏不应成为博客服务启动的硬依赖；终端渲染不能直接充当网页界面。
- 新增主体：博客读写适配、文章/批次任务状态、身份权限、审批版本、发布幂等与远端版本冲突、文章检索与引用、后台任务接口与网页进度、usage 指标及领域评测。

不按行数声称已经完成某个产品百分比：核心执行机制复用度高，但完整博客产品仍有大量业务工作。

## 当前具体限制

1. 最新 conversation.py 已将 LOCAL_TOOLS 加入多轮工具列表；此前“文件搜索仅在旧 task 入口”的结论已过时。
2. 最新代码已新增 reasoning.py 与 --reasoning-effort；这是配置/记录基础，不是质量/成本对照实验结果。
3. SkillConversation 仍要求 search_skills/get_skill；状态 kind、library_file、10 轮上限与开场词绑定 Skill 业务，需要参数化或拆出业务配置。
4. find_text 返回路径和行号，不返回文章片段或全文。它不是完整的博客问答检索器；需补有来源、版本、长度上限的文章读取与片段检索。
5. finish_pending 保存工具调用后执行，恢复未完成调用；failed 也被标记为已处理。attempts 计数和 max_steps 不等于按错误类别、次数与总时长控制的重试策略。SDK 自带行为另核查，不应声称系统已有完整重试。
6. Skill 按 ID 去重只覆盖本地收藏场景；远端发布成功而检查点未提交的窗口需要服务端幂等键或操作查询。
7. 原子 JSON 避免半写文件，不解决多进程并发写入和任务抢占；网页后台需要按任务隔离及串行执行/租约策略。
8. 现有 hook 主要是展示与 SessionEnd；这些失败可回退，但权限校验失败必须阻止副作用。
9. agent_core 搜索未发现 usage/cached_tokens/perf_counter/backoff 等观测或重试实现，仍需补指标与实验；不能从上下文字节数推算真实 token 成本。

## 建议迭代

1. 固定基线：保留现有 CLI；先运行已有测试，新增模型/工具/压缩事件的指标记录和 5—10 个文章用例。
2. 解开 Skill 业务绑定，接入只读 search_posts/read_post，做出能引用原文、资料不足会说明的问答模式；保留通用主循环和上下文模块。
3. 管理模式仅生成整理/翻译/摘要建议；批准具体版本后保存/发布，增加副作用权限、幂等和失败恢复。
4. 扩展批量任务与网页操作，加入真实缓存/推理对照；确保重启、取消和部分失败可验证。
5. 最后按学习需要添加小规模子 Agent 审校实验，与单 Agent 基线比较，收益不明确就保持可选。

当前仅评估与记录，未修改 Agent 实现、博客业务代码或学习路线原文。
