# 页面与对话栏设计基线

状态：交互规范与线框；2026-10-26已实现 `/assistant` 开发夹具，尚无真实服务连接。生产默认404，双语/状态模拟不代表后端能力。遵守 DESIGN_SPEC 的五档字号、字体/色板单入口和双语字典，不引入组件库或状态库。

## 1. 入口与布局

首版 `/assistant` 是可独立分享的完整页面，保留现有首页场景。正式接入后从 Blog 导航区域增加轻量入口；文章详情可增加“询问本文”传 postId，不把文章正文塞入 URL。修改 `/blog` 本身前，按既有规范确认该轮是否包含书架/双链等新增需求；这些改版不阻塞独立问答页。

桌面沿用站点 1120px 容器：左侧约 1/3 说明当前能力/来源范围，右侧约 2/3 对话。移动端说明折叠为页头，消息与输入单列；首版不用全站悬浮球，避免与 Hero、滚动和移动键盘争用视口。未来抽屉复用同一 ChatSession，不另建会话逻辑。

```text
导航                                            EN / 中
┌──────────────────┬──────────────────────────────────┐
│ Blog Assistant   │ 开场白 / 提问示例（静态、双语）  │
│ 当前可用范围     │ 用户问题                         │
│ 博客 / 联网状态  │ 助手回答 + 可点击来源             │
│ 新对话           │ ▸ 查看过程：真实阶段、耗时         │
│ 退出对话         │                                  │
│ 剩余额度阶段     │ 新消息提示 / 回到底部              │
│                  ├──────────────────────────────────┤
│                  │ 多行输入              发送/停止   │
└──────────────────┴──────────────────────────────────┘
```

字号：页面名 heading，说明和正文 body，状态/来源 caption；不用新的微型字号。回答主文本直接排版，角色/留白区分消息，强调色只用于焦点和链接。管理页采用功能性分栏：原稿 / 待审稿 / 差异与审批，不共享公开聊天历史。

## 2. 状态矩阵

| 状态 | 展示 | 输入与操作 |
| --- | --- | --- |
| 新会话 | 固定开场白；按真实能力给例题 | 可输入；开场白不消耗模型，恢复不重复 |
| queued | 排队状态，不造百分比 | 禁止重复发送；可取消 |
| running | 实际阶段；已核验内容到达才展示 | 输入草稿可编辑；按钮为停止；每会话仅一在途 |
| reconnecting | 已断线、正在恢复订阅 | 保留正文；不自动重发问题 |
| completed | 最终回答、来源、实际联网标识 | 可追问、新对话 |
| partial / timed_out / failed | 保留有效内容、明确未完成与原因 | 显式重试；提示会产生新 run/可能额外用量 |
| cancelling / cancelled | 等待确认 / 已停止 | 取消确认前不宣称停止成功 |
| closed | 已退出，消息仍可查看 | 显式重新开始；额度不重置 |
| expired | 会话已到期 | 新建，不伪造历史恢复 |
| warned / fallback / blocked | 服务端额度提示、预设回复标识或关闭说明 | fallback/blocked 不调用模型/MCP |
| source invalidated | 原答案内容已失效 | 不继续显示已撤回来源的旧正文 |
| service unavailable | Agent 暂不可用，博客浏览仍可用 | 保留本地输入草稿，可稍后重试 |

“停止”“退出”“额度触发关闭”是三种行为。彩蛋为后续 USER-6/7，默认静态退出提示，在 reduced-motion 下不依赖动画；未建语料库时仅用字典固定提示，不能伪称命中。

## 3. 组件与数据流

Server page 输出标题/metadata/页面壳；`assistant-session.tsx` 管 React reducer 和连接生命周期；`message-list`、`message-item`、`source-list`、`process-timeline`、`composer` 分别接收有限 props。服务端 snapshot 是消息和状态权威，浏览器仅保存尚未发送的草稿、展开状态和最后 cursor；localStorage 不存身份凭据或完整聊天库。

Transport Interface：发送命令、取 snapshot、订阅事件、取消订阅。先提供固定 fixtures adapter，再接真实 server adapter；两种使用同一事件 reducer。消息 key 为服务端 ID，乐观用户消息以 clientRequestId 对账。locale 切换改变 UI 字典，不翻译既有消息或偷偷重跑模型。

消息 Markdown 复用现有安全渲染管线，禁原始 HTML、脚本 URL 和自动加载任意远程图片；外链标识、noopener/noreferrer。引用卡只接收服务端通过的结构化来源，不从模型任意 Markdown 构造本站可信引用。

## 4. 可访问性与输入

- Enter 发送、Shift+Enter 换行；中文 IME composition 时 Enter 不发送。
- 消息区域固定高度并独立滚动，输入区在面板内保持于消息之后；2026-10-26预览采用正常文档流，避免 `sticky bottom` 提前覆盖消息。考虑移动 `dvh`、安全区、软键盘遮挡，360px 无横向滚动；真实手机键盘仍需后续验收。
- 用户离底后停止自动滚动，只显示新消息提示；阅读代码/选择文本时不抢位置。
- `aria-live=polite` 宣布阶段和最终完成，不逐 token 朗读；按钮有可访问名称，错误与输入关联，退出后焦点可恢复。
- 过程默认折叠，只显示真实检索/读取/生成摘要，不显示隐藏推理、原始工具参数、本地文件路径、trace 或管理员内容。
- 无新增动画预算；必要过渡复用 motion tokens/useGSAP，减少动态效果下直接切换。

验收桌面 1280px、移动 390px/360px、键盘/IME、断网恢复、快速连点、来源撤回、长代码/表格、双语和 reduced-motion。前端 mock 通过不代表后端已连接。
