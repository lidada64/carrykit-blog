# W6 · 涟漪求解器(`ripple.ts` / `ripple.glsl.ts`)

> 2026-09-04。承接 `docs/water-orb-coupling.md` 的体例:先给数字,再给坑,不给形容词。
> **只对 mid 与 night 定标**;near 按用户要求保持现状,涟漪在它上面关闭、preset 一字未改。

---

## 1. 要修的是什么

改造前 `water-dither.tsx` 的涟漪是 `sin(d*30-t*6)*exp(-d*7)` —— **锚在光标上的驻波**,
而且用屏幕 uv,相机高度一变整片滑动。W6 真解波动方程,涟漪锚在世界坐标里。

## 2. 数值方案

256×256 RG16F ping-pong,R = h(n),G = h(n−1)。显式蛙跳:

```
h_new = (2h − h_prev + C²·∇²h) · damping,   C = c·Δt/Δx
```

`RIPPLE_CFL_MAX = 0.7` 在 `RippleSolver` 里是**断言**,不是注释:
构造时算出 `maxDt = 0.7·Δx/c` 并在 `stepFixed` 里检查,越界直接抛。

边界用**海绵层**(外圈 24 纹素逐步阻尼),不是 CLAMP 也不是 REPEAT ——
CLAMP 会在边界留一条直线,REPEAT 会出现幽灵涟漪。

消费端 `waterRipple(p)` 返回 `(h, ∂h/∂x, ∂h/∂y)`,**同时加进 `waterWaveField` 的
`h` 与 `grad`**。只加高度会出现「看得见涟漪但法线不动」。
按 `fwidth` 求出的 footprint 淡出(`uRippleLodBias`),否则远处闪成噪点;
淡掉的能量**不**转进 σ² —— 涟漪是瞬态的,不是稳态谱,进 σ² 等于让一次冲击
永久抬高远处的粗糙度。

**涟漪不被风阵斑块/波脊断裂压制。** 那两层调的是波幅倍率,涟漪是加性高度:
镜面区照样能被石子砸出涟漪,这是物理,不是实现方便。

## 3. 前沿判据(坑 13)

第一版用「当前环峰的 10%」当前沿阈值,量出来是 **11 / 15 / 13 / 9 / 12 / 15 纹素** ——
非单调,完全读不出匀速。

根因:**环峰本身在振荡**。初始高斯分裂成内外两支,内支收敛回圆心再反弹,
`argmax` 在圆心与环之间来回跳,拿它当分母的话前沿跟着跳。

改成**绝对阈值**(首个冲击幅度的 2%)之后就是干净的 d'Alembert 支撑边界
(`r > c·t + 3σ` 之外恒为 0):

| preset | 前沿(纹素,10→50 步) | 实测速度 | 名义 c |
|---|---|---|---|
| mid | 11 → 18 | **0.34~0.39 m/s** | 0.45 |
| night | 13 → 19 | **1.46 m/s** | 2.0 |

单调,步长恒定。比名义 c 低 13~27% 是数值色散;把 Courant 数从 0.23 提到 0.46
测速**不变**,所以不是 CFL 余量的问题,是离散拉普拉斯对高波数的相速度衰减。

## 4. 两个 preset 各自定标(本卡最重要的一条)

**交互的世界尺度必须跟着相机尺度走,一套参数三个 preset 通用是幻想。**
这与 W5 灯球的 `worldRadius` 要 0.07 / 0.22 / 1.8 m 是同一件事。

| | mid | night |
|---|---|---|
| 可见水面 | 2.0 → 24.8 m | 24.2 → 270 m |
| 覆盖区域 | 8 m @ (−4, 2) | **40 m @ (−20, 24)** |
| Δx | 31.25 mm | 156 mm |
| 波速 c | 0.45 m/s(10 cm 毛细-重力波) | **2.0 m/s(2 m 重力波)** |
| Courant | 0.23 | 0.205 |
| 冲击 | 0.15 m / 6 mm(雨点) | **2.5 m / 60 mm** |
| 消费增益 amp | 4.0 | 4.0 |
| 翻动像素 | 2525(0.12%) | 2116(0.10%) |

night 用 mid 那套的话:32 m 处屏幕尺度只有 ~53 px/m,0.15 m 的雨点在屏幕上是
**8 px**,一个抖动单元都填不满 —— 实测只翻动 81 个像素(0.00%)。这是
**§14 坑 12「分数对画框外的东西完全免疫」的同类**:九项指标一位不差,图上什么都没有。

`amp` 为什么必须 4.0:涟漪的斜率 a·k ≈ 0.018,而波场自己的 |∇h| p99 是 **0.12**,
差 6 倍 —— 1.0 时几乎推不动任何像素跨过环境列那条岸线边界(只翻动 0.03%)。

## 6. 没做到的

- **真实 GPU 帧时间**(0.3 ms 预算)未测,容器无显卡 —— 归 W9。
- **5 分钟连续跑**只验到 NaN 计数为 0 的短程,没跑满 5 分钟。
- 预览台的涟漪是**点击注入**;计划 §4-W7 那条「pointermove 速度阈值 + 40 ms 节流」
  的连续注入归 W7 的 WaterDirector。
- `prefers-reduced-motion` 下预览台随波场一起定格(`playing` 为假时不 `stepFixed`),
  但正式组件里的接线归 W8。
