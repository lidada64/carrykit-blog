# 水面视觉标尺 (W0) — 指标定义、基线与用法

> 状态:2026-09-02 完成。这把尺子是 `docs/` 里「灯球照水」计划 W0 的产出,
> **W2~W9 每一张任务卡的验收都跑它**,不再靠肉眼说「看着还行」。
> 相关:`scripts/water-metrics.mjs`(评分器)、`scripts/water-harness.mjs`(黄金帧渲染台)。

---

## 1. 为什么需要一把尺子

「像不像奥伯拉丁 / 像不像那张照片」如果不落成数字,多个人(或多个 agent)并行调参时
无法收敛:每个人心里的「像」不一样,而且改一处参数往往按下葫芦浮起瓢。把参考图量化成
8 个指标之后,收活变成一次跑分,PR 里贴的是分数表而不是形容词。

尺子本身也必须可复现,所以三张参考图缩到统一尺寸后**入库**在 `docs/water-refs/`
(共 ~800KB),任何人都能 `npm run water:baseline` 复算一遍。

---

## 2. 分析约定

固定这些约定,否则不同分辨率、不同 dpr 的图之间不可比:

| 项 | 约定 | 理由 |
|---|---|---|
| 分析分辨率 | 统一缩到**高度 1200px、保持宽高比** | 以 px 计的指标(波长、划线长度)需要共同基准;高度归一才让分带统计对齐 |
| 去趋势 | 减掉 **41px 盒模糊** | 只留波纹这一档的局部结构,大尺度明暗(天光、岸影)不参与 |
| 分带 | 屏幕高度均分 **10 带**,band 0 = 顶端 = 远 | 对比度沿景深的分布是核心判据 |
| 带内展度 | 每列 RMS 的 **40 分位数**,不是整带 RMS | 见 §4 的坑 1 |
| 1-bit 输入 | 先局部平均**反抖动**还原密度场再统计 | 见 §4 的坑 2 |
| 特征侧 polarity | `near`/`mid` = 暗划线,`obra` = 亮墨点 | 跟着 baseline 走,不自动猜 |

## 3. 八项指标

| 指标 | 权重 | 定义 | 抓的是哪种失败 |
|---|---|---|---|
| `foregroundFlatness` | **0.20** | 末两带展度 / 峰值带展度 | 把最大对比度堆在前景——最常见、最致命 |
| `coherence` | **0.20** | 峰值带结构张量 (λ₁−λ₂)/(λ₁+λ₂) | 波纹退化成各向同性噪点,读作沙子不是水 |
| `curveCorrelation` | 0.15 | 归一分带曲线与基线的皮尔逊相关 | 亮度沿景深的整体分布跑偏 |
| `peakBand` | 0.10 | 峰值所在带 0..9 | 掠射带位置错(逆投影或地平线设错) |
| `dashAspect` | 0.10 | 特征游程 宽/高 中位数(按对比度够的几带取中位) | 暗部是圆点不是短划 |
| `gradAngleDeg` | 0.10 | 主梯度角,归一到 [0,180),90 = 横向条纹 | 风向参考系接错 |
| `featureCoverage` | 0.10 | 峰值带特征像素占比 % | 整体过曝或过暗 |
| `gridArtifact` | 0.05 | 高频段(>0.4×Nyquist)落在孤立谱峰上的能量占比 % | 有序抖动(Bayer)的网纹残留 |

**加权总分 ≥ 0.80 视为达标。** 某项基线为 `null` 时不计分,其余权重按比例归一。

### 为什么 foregroundFlatness 权重最高

三张参考图的分带对比度**全是单峰**:峰落在「掠射角使 Fresnel 反射率陡升」与
「波长仍可分辨、未被逐像素平均」两个条件的交点上;最靠近相机的前景只有峰值的
0~7%,因为那里视角最陡、F0≈0.02 的菲涅耳反射率极低,看进的是水体而不是天空,
水面读作玻璃。

而绝大多数水面 shader(**包括本仓库改造前的 `water-dither.tsx`**)把最大对比度
堆在离相机最近的地方,方向正好反了。这一项一票否决。

## 4. 造尺子时踩到的两个坑(都改变了算法)

### 坑 1 · 整带 RMS 会被一条窄亮光路带偏

第一版用整带 RMS 当展度,结果奥伯拉丁那张的 `foregroundFlatness` 量出 **0.51**,
看起来「前景一点也不平」——与结论矛盾。查下去发现:画面下缘有一条又窄又亮的
**月光路径**(镜面高光打穿了平静的前景),整带 RMS 被它抬起来了。

环境水面的平静与镜面光路的明亮是**两件事**,这条指标只该量前者。改成取
**每列 RMS 的 40 分位数**:忽略掉少数被光路占据的列,量的是「典型一列有多静」。
对没有窄亮特征的照片类参考,它与整带 RMS 几乎一致(near 0.112→0.030,mid 0.072→0.065),
而奥伯拉丁降到 **0.00**,三张参考这才一致。

> 对后续任务卡的含义:**灯球在水面投下的光斑不该被算作「前景不平」的证据**。
> 光斑该亮,环境水面该静,两者并存才是对的。

### 坑 2 · 直接对 1-bit 图算局部 RMS,量到的是抖动噪声

奥伯拉丁截图是硬 1-bit(81.1% 像素是一个暗色 `#32331A`,3.8% 是一个亮色 `#E6FEFD`)。
对它直接算局部 RMS,只要有墨点的地方 RMS 就一样高,分带曲线整片糊平,
`featureCoverage` 量出 15.5% 而不是实际的 36.6%。

改成先检测「有效 1-bit」(两个色调覆盖 ≥85% 像素),然后:
- **field**(用于分带展度 / 相干度 / 波长)= 二值图的 9px 局部平均,**反抖动**还原出量化之前的密度场;
- **ink**(用于 `dashAspect` / `gridArtifact`)= 二值墨点本身。

改完 `featureCoverage` 36.6%(基线 36.8%)、`gradAngle` 90.2°、曲线相关 0.979。

> 这一步不是为了迁就参考图——**我们自己的产出也是 1-bit 抖动输出**,不做反抖动
> 就没法给自己打分。

### 附带修正 · `dashAspect` 没有全局目标

原计划写的是「≥2.5」。实测发现横向拉长是**中景那一档**的特征(3.5),
近景特写在峰值带本就接近方形(1.5),奥伯拉丁用的是各向同性抖动(1.0)。
所以改成按各自 baseline 的值打分,相对误差 40% 以内满分。

| **自评总分** | **0.983** | **0.983** | **1.000** |

归一分带曲线(band 0 → 9):

```
near  0.269 0.453 0.685 0.812 0.970 1.000 0.561 0.325 0.034 0.026
mid   0.407 0.603 0.542 0.944 1.000 0.562 0.049 0.043 0.047 0.083
obra  0.000 0.003 0.034 0.128 0.057 0.117 0.326 1.000 0.000 0.000
```

`obra` 的 coherence 实测 0.608 但**不作为目标**:反抖动还原的密度场里占主导的是
地平线那条横向强眩光带,量到的是眩光的各向异性而不是水面波纹的。夜景 preset 的
波纹各向异性沿用 near/mid 的 0.93~0.97 要求。

## 6. 改造前的 `water-dither.tsx` 跑分

黄金帧:`golden/baseline/current-t{0,1.0,2.5,5.0}.png`(1920×1080, dpr=1, 固定 uTime)。
对照 `mid` 基线:

| 指标 | 实测 | 基线 | 判定 |
|---|---|---|---|
| foregroundFlatness | 0.356 | 0.065 | **FAIL** |
| coherence | **0.003** | 0.974 | **FAIL** |
| curveCorrelation | 0.579 | 1 | WARN |
| peakBand | 2 | 4 | WARN |
| dashAspect | 1.0 | 3.5 | **FAIL** |
| gradAngleDeg | 44.4 | 91.7 | **FAIL** |
| featureCoverage % | 20.5 | 19.6 | PASS |
| gridArtifact % | **64.37** | 0 | **FAIL** |
| **加权总分** | **0.274** | — | **未达标** |

分带 RMS `[17.1, 61.0, 66.7, 46.4, 34.5, 31.1, 16.3, 18.7, 17.5, 29.9]`
——峰在 band 2、前景又翘起来,是「双峰 + 前景不静」,与参考的单峰完全不同。

**读数**:

1. **相干度 0.003** 几乎是完美的各向同性。双层域扭曲 `uWarp*(0.42·warp1+0.22·warp2)`
   加 `flowBend*11.0` 的相位扰动把波脊揉成了噪声,梯度角 44.4° 说明连一个主方向都没有。
   → W2 要把扰动强度降到相干度 ≥0.85。
2. **谱尖峰度 64.37%** —— 高频能量的三分之二住在 Bayer 8×8 的网格谐波上。
   `NEXT.md` 里那句「满屏纸碎屑」现在有了数字。→ W4 换蓝噪声。
3. **前景平坦度 0.356 + 峰值带在 2** —— 没有逆投影、没有 Fresnel,
   对比度既不压缩也不成带。→ W2 的透视映射 + W3 的菲涅耳。
4. 唯一及格的是 `featureCoverage`(20.5% vs 19.6%),说明整体曝光是对的,
   问题全在结构而不在明暗。

## 7. 用法

```bash
npm run water:baseline                    # 自检:对三张参考图复算,验证尺子没漂
npm run water:metrics -- <img> --baseline near|mid|obra [--json]
npm run water:frame -- --shader <f.frag|.glsl.ts> --out golden/x.png --time 2.5 [--cost]
```

`water-harness.mjs` 固定 1920×1080 / dpr=1 / `uTime` 由 `--time` 显式给定
(**绝不用 `performance.now()`**)/ `preserveDrawingBuffer`,这是计划 §5 的黄金帧协议。
它同时探测 WebGL2 能力并打印渲染器名。

### 一个必须知道的限制

本项目的云端开发容器没有 GPU,headless Chromium 走 SwiftShader 软件光栅,
所以 `--cost` 报的是**软件光栅每帧墙钟时间**,只能做路线之间的**相对**比较
(软件光栅耗时随每像素 ALU 量增长,恰好是区分方案的那个量),**不是 GPU 预算值**。
真实 GPU 帧时间必须在有显卡的机器上用 `EXT_disjoint_timer_query_webgl2` 量,
这件事归 W9。

改动 `water-metrics.mjs` 的任何算法后,必须重跑 `npm run water:baseline`
并把新值同步回脚本里的 `BASELINES`,否则所有卡的验收都会一起漂移。
