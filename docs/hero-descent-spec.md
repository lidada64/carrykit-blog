# Hero 下潜展示规范

更新：2026-10-26。状态：方案定稿、待视觉原型验证；未实现、未上线。本文是 Hero 后续开发的唯一现行规格。PRD 管需求入口，TASKS 管完成状态；不要从旧日期追加记录推导新要求。

## 1. 范围与事实边界

用户确定：灯球像潜水艇随下滑向下探；前景灯球、后景包围式曲面展示；依次经过 Blog、Work、Radar；CARRYKIT IS NOT JUST 字幕先伴随灯球加速、变亮，从右侧带鱼眼畸变快速进入，慢速播报，再像被抽水一样快速离开。重点是成品质感，不以画面描述或编译成功代替视觉验收。

本方案取代旧的吊起悬挂、变字母 O、星环、凹槽咬合和卷纸转场作为新 Hero 开发目标。当前正式首页仍为 CampfireHero 单屏；下潜未接入，旧吊起调试仍在 Lab。文档定稿不自动改变线上行为。

首阶段只验证真实灯球＋归档文案文字墙＋曲面＋一次进退场＋Blog 章节。通过后扩展 Work/Radar，最后接正式首页。不在本任务改造三个独立内容页、接 Agent API、添加物件检视或重做人物资产。

### 当前基线，实施前复核 token 与运行页面

- 固定居中近景，后景 CarryKit. 标题；沿用现有本地字体、主题色和哑光格纹/1-bit 默认。
- 默认 Orbit −34°、Elevation 12°，亮度27、密度86是最近记录的基线；实际代码若不同先记录差异，不静默恢复历史参数。
- 人物、篝火和三物件继续存在；物件目前直接导航，检视方案不在此次范围。
- 正式首页隐藏顶部标识/菜单及调节控件；Lab 保留控制。其他页面导航不受本方案影响。
- 每次进入首页播放 loading：000→090，等待场景完整首帧、两次绘制帧与既有安全延迟，再至100揭幕；数字不是下载字节百分比。减少动态跳过演出但仍等 ready；失败必须释放遮罩并提供可用入口。
- 新章节资源按需加载，不把全部章节就绪变成首屏 loading 的前提。

## 2. 构图与空间规则

灯球是主体，后景是连续空间。近景拉远后开始下潜，相机略滞后再跟随；相机跟上后球仍在中下部，章节向上经过。通过相对运动表达持续下潜，不让球持续下降到屏幕外。

- 路径以纵向为主。少量横向偏移只用于避让，不每章左右跳位，不无限漂浮或弹跳。
- 后景曲面超出画面边界，不画显示器边框。中央清楚、两侧后退压缩并变暗。文字、图片、章节名共享同一透视和曲率。
- 前景颗粒少而快，远景慢；颗粒仅辅助深度，不能遮住文字或成为主要视觉。
- 球体可遮挡章节大标题一小部分；正文、可点击入口有独立安全区，不落在球体后方。
- 不复用旧标题梯形挖空/绕排作为球体遮挡。由球体真实轮廓遮挡后景，避免可见空白框。
- 初始拉远与下降连续，近景末帧必须等于下潜首帧；退出时释放正常页面滚动，不再接吊起终态。

试作参数（不是用户已确认的最终值）：拉远后球径为视口宽18–24%，必须再受视口高度和移动端主体可读性约束；中央约半屏宽为易读区。固定五帧：近景、完整球、鱼眼峰值、稳定播报、抽吸中段。

## 3. 字幕演出：墙体运动与墙内播报分开

沿用归档文字墙的重复、密铺、错行与隔行反向，不改成单条跑马灯。短语为 CARRYKIT IS NOT JUST；正式文案接双语字典，中文版本另排，不硬编码组件字符串。

| 阶段 | 灯球 | 后景 | 验收重点 |
| --- | --- | --- | --- |
| 蓄力 | 下潜变缓，转速先加快，亮度稍后升起 | 保持安静，避免提前抢戏 | 因果顺序可见；不是所有参数同时线性变化 |
| 冲入 | 保持稳定轮廓，亮度峰值仍有暗缝 | 整墙从右侧弧面深处同向进入；中心鱼眼鼓胀，边缘压缩 | 有统一主方向，非奇偶行同时左右乱冲 |
| 刹停 | 转速与亮度缓落 | 墙体急减速、无弹性回弹；鱼眼回落至稳定曲率 | 速度连续，字形恢复清楚 |
| 播报 | 缓慢下潜或停留，主次稳定 | 墙体不漂移，内部隔行反向缓慢无缝滚动 | 中央可读，接缝不可见，无每帧重排 |
| 抽离 | 暂不叠加大幅路径运动 | 以左下为首轮消失点，整墙统一汇聚；各行错时拉长、弯曲、收窄后消失 | 先形变再离场，非整体快速平移/透明度归零 |
| 余韵 | 亮度与转速回到稳定，下潜恢复 | 清空短暂留白，再进入章节 | 无残影、亮度突跳或第二次闪光 |

曲面是稳定结构，鱼眼是短时畸变，抽吸是退场形变，三个参数独立。只扭曲后景，不让灯球跟着鼓包。若整面屏幕轮廓也需卷入，必须形变网格；只改 UV 不足。

样片时间初值：0.5s蓄力＋0.5s冲入＋3s播报＋0.7s抽离＋0.3s余韵。它是对比样片，不是正式锁滚时长；实际值经录像比较后固化到 motion tokens。播报期间至少有一条完整短语能自然读完。

## 4. 三章节内容与总节奏

| 滚动进度初值 | 场景 | 内容/进入方式 |
| --- | --- | --- |
| 0–12% | 拉远并建立下潜 | 保持当前首屏辨识度 |
| 12–28% | 字幕强演出 | 完整冲入/抽离只使用一次 |
| 28–50% | 01 Blog | 精选标题与少量摘要，文字档案在曲面展开；稳定入口到 /blog |
| 50–73% | 02 Work | 一次突出一个真实作品主画面与一句说明；入口到 /work |
| 73–94% | 03 Radar | 音乐/电影/游戏/文摘/工具的精选收藏构图；入口到 /radar |
| 94–100% | 收尾 | 相机停止跟随，章节收束并释放正常滚动 |

比例仅供试作，不绑定固定屏数。三章沿用同一空间，不各自重演鱼眼/爆闪。内容稳定后再开放对应交互；过渡中不让热区与变形画面错位。内容优先用已有已发布数据；缺图/无内容显示明确的静态替代，不虚构作品，不因空内容卡住演出。具体精选数量、Radar素材、收尾接页脚还是其他正文，均在原型后确定。

## 5. 尚未裁决的视觉选择

以下是待对照验证项，不得当成用户已批准或已实现：

1. **转速含义**：真实球体转动与光纹加速两版对照。不能把人物/篝火一起高速甩动；若球体单独转，要检查接触点滑动、阴影与反射。光纹版不得宣称等同真实网格旋转。
2. **双色与光晕**：A保持严格双色，以覆盖率/颗粒表达亮度；B主体双色、后景允许有限连续明暗。B改变现行视觉约束，先在Lab比较，再由用户选定；正式默认不擅自放宽。禁止整张1-bit画面加模糊。
3. **抽吸方向和强度**：首轮左下消失点，评估是否影响下一章方向感；文字必须先可读，畸变峰值不能占据整个阅读段。
4. **章节收尾与素材**：先用真实现有内容验证，尚未选择的排版、数量、最后一屏不提前写成最终设计。

## 6. 技术路线与模块职责

现有 Next.js/TypeScript/Tailwind/GSAP/原生WebGL足够。首轮不加依赖，不迁移框架。现有WebGL1灯球有自定义材质、阴影、反射和资源清理；新增能力尚无性能证据。

- 演出组件位于 src/components/motion/，useGSAP统一管理生命周期，motion tokens管理时间/位置/亮度/畸变参数。
- 一个主Canvas/渲染循环，后景曲面与前景主体共享投影。需要局部后处理时才用离屏缓冲，不默认多Canvas或多套引擎叠加。
- 曲面网格负责透视，独立GLSL参数负责鱼眼/抽吸；选择性发光不得使人物、火焰跟着过曝。
- 字体加载后Canvas绘制字幕纹理；GPU移动采样坐标。只在内容/语言/字体/必要尺寸变化时重建，禁止逐帧DOM截图或纹理上传。
- WebGL1需处理非2次幂纹理的重复采样/mipmap限制；查询能力并限制最大纹理尺寸。字号来自已有token，采样分辨率与UI字号分开。
- 峰值放大需清晰，两侧缩小需避免摩尔纹/闪烁。普通纹理确实不足再评估SDF/MSDF，不先增加复杂度。
- 后景、球体与最终输出统一色彩空间、透明度和量化顺序；防重复gamma转换、透明边缘黑边和全屏过曝。
- HTML保留真实标题/说明/链接，Canvas装饰不替代语义。交互层与视觉数据同源；入口尽量固定在稳定区，避免为扭曲文字做精细点击。
- Next.js服务端保留内容与静态兜底，客户端加载演出。数据库、鉴权、部署不因本效果变更。
- 现有材质、人物姿态、资源格式、loading与其他页面动效是回归基线；新功能不顺手重构整个渲染器。

Three.js只有在场景对象、灯光、后处理组合持续扩张，或原生实现维护成本经原型证明过高时再评估。迁移必须计入双色材质、火焰、阴影、资产与热区回归，并获新大型依赖授权。R3F、WebGPU、物理引擎不是本效果前置条件。Blender可做参考片/局部资产，不以整段视频默认替换交互。

## 7. 滚动与时间控制契约

推荐混合驱动，Lab验证后定版：滚动负责深度/相机/章节；时间负责短促蓄力、冲入、抽离；持续时钟负责播报/火焰/弱自转。同一输出参数只有一个最终写入者，合成后交给渲染器；不以每帧React setState驱动。

建议阶段：intro → descent → broadcast-enter → broadcast-read → broadcast-exit → blog → work → radar → release；阶段与局部进度分开。正向短动画不排队，反向从当前值过渡。Lab需要可冻结帧的确定性seek模式，不能让独立时钟破坏五帧复现。

| 输入/异常 | 必须行为 |
| --- | --- |
| 停滚 | 深度停止；短促入场可收尾，稳定播报继续；减少动态全部静止 |
| 快滑跨区 | 直接收敛到目标章节，不补播已过期演出 |
| 中途反向 | 平滑退出/返回，不跳回起点；边界有重入抑制，防反复闪亮 |
| 返回页面/刷新在中段 | 恢复相应进度或静态章节，不强制重新演完整开场 |
| resize/横竖屏/地址栏变化 | 重算必要布局并保留章节；防频繁refresh抖动 |
| 后台恢复 | 限制时间步长，不累积大跳帧 |
| 链接、键盘、触摸 | 原生导航可用，不吞控件输入；提供跳过演出入口 |
| 卸载/错误/context lost | 取消动画、事件、加载与GPU资源；恢复正常滚动，显示静态入口 |

不沿用旧吊起Observer的永久preventDefault方式。优先原生滚动配合ScrollTrigger；首页不叠加ScrollSmoother。短演出不锁住整页。自动播放与严格跟手不可能同时固定节奏，原型必须验证此取舍，不承诺每种滚速都有完全相同电影节奏。

## 8. 性能、加载与降级

- 最重帧按灯球＋字幕畸变＋光晕同时出现测量，不只测静止球体。
- 纹理只保留当前/必要相邻章节；图片预解码，首次字幕shader尽量提前准备，避免触发点编译卡顿。
- 光晕可用低分辨率；限制DPR、颗粒和反射更新频率。主题色/布局读数按事件缓存，不逐帧强制布局。
- 2048² RGBA8纹理约16MiB，完整mipmap约21.3MiB，不等于压缩下载大小；同时预算深度/离屏缓冲和模型纹理。
- 目标桌面60fps，16.7ms为整帧预算而非JS提交耗时。记录设备/浏览器/分辨率/DPR、帧时间分布与长卡顿；GPU耗时可测时记录，不可测明确注明。
- 手机独立构图与质量档：减少行数、图片、后处理；必要时静态后景。真实iOS Safari/Android Chrome、桌面集显需验证，模拟窄屏不能替代真机。
- 连续运行检查温升降频、内存增长、页面往返资源释放。不得仅用平均FPS宣称流畅。
- WebGL不可用或上下文恢复失败仍有静态章节；减少动态直接静态内容，不保留高速冲入、旋转、抽吸。
- 所有资源使用现有同源或受支持来源；远程图转纹理需核对CORS，失败有占位，不能污染Canvas或阻断整段。

## 9. 交付关卡与不通过条件

1. **静帧关卡**：五关键帧使用真实资产和字体；确认比例、遮挡、曲率、亮度。出现贴图拼贴感、白圆、正文遮挡、明显空白遮罩即返工。
2. **时间样片关卡**：同构图两档节奏录屏；确认蓄力因果、刹停无回弹、播报可读、抽吸先形变。一次只改一类参数，保存参数与录像对应关系。
3. **输入关卡**：慢滚/正常/快滑跨段/反向/边界反复/键盘/跳过/返回/resize/后台恢复逐项检查。无锁滚、重复播放、旧动画覆盖新状态。
4. **内容关卡**：Blog先通过，再接Work/Radar；中英、长标题、空内容、缺图、链接和焦点正常。
5. **性能与降级关卡**：目标设备最重片段、持续运行、减少动态、加载失败/context loss有证据。未测设备列待验，不以HTTP200代替目测。
6. **上线关卡**：npm run lint与npm run build通过；npm run dev实际页面视觉验收。Lab结果得到用户视觉确认后才替换正式Hero；本条区分审美选型，不要求对已授权的例行实现反复确认。

交付证据包含：五帧、正常速度录像、输入/异常结果、设备参数、质量档、性能范围、未验证项。禁止只交“动画已完成”或技术名词。方案定稿不等于效果已通过。
