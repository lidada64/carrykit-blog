# Blender 资产铺垫与复用性 (Blender Asset Foundation)

> 路线:**路线 2 — Blender 预渲染**。所有 3D 资产在 Blender 建模 + 渲染,导出为**透明背景**的图像序列 / sprite / alpha 视频,前端用 GSAP + CSS 编排。
> 服务对象:[`docs/homepage-animation-plan.md`](homepage-animation-plan.md)(主页动画)+ 未来 radar 等页面。
> 核心策略:**一次搭好"主控场景",让灯球的模型/灯光/材质/HDRI/渲染预设可被后续所有 3D 资产复用**。

---

## 0. 资产管线(所有资产统一流程)

```
Blender 主控场景(模型 + 灯光rig + HDRI + 材质库 + 渲染预设)
      │  (Cycles 离线渲染, Film 透明)
      ▼
透明背景帧序列 (PNG, 直出 @2x)
      │  (打包/转码)
      ▼
交付前端: ① sprite sheet(.webp, CSS background-position 步进)     ← 主用,兼容性最好
          ② webm VP9-alpha + Safari HEVC-alpha 回退              ← 帧多/体积大时用
      │
      ▼
前端序列播放器(无缝循环 + scroll 变速) + CSS 发光叠层
```

## A. 可复用主控(最高杠杆,一次投入,全站受益)

> 这些不是"页面素材",而是产出所有素材的**母体**。做主页灯球时就要按可复用标准搭建。

| ID | 内容 | 复用价值 |
|---|---|---|
| **M-1 主控场景** | 一个 `.blend`:迪斯科球模型 + 摄像机预设 + 世界设置 | 所有后续 3D 资产在此扩展,避免重复搭台 |
| **M-2 灯光 rig** | 舞台彩色点光 + 主光/补光,营造迪斯科反光碎片 | 任何镜面/金属资产复用,保证全站打光一致 |
| **M-3 HDRI / 环境贴图** | 一张用于 chrome 反射的 studio/city 环境 | **强复用**:灯球、黑胶、奖杯等任何反光物共用一套反射环境 |
| **M-4 材质库** | Chrome/镜面 PBR、Emissive 发光、玻璃 | 灯球镜片、黑胶唱片、游戏奖杯/奖章等直接取用 |
| **M-5 渲染预设** | 分辨率、采样、透明 Film、色彩管理、命名规范 | 所有资产视觉一致、批量出图无需反复调参 |

## B. 主页动画必需资产(现在就要产出)

> 关键发现:主页 8 拍里,**灯球只需 2 个渲染产出**,其余"缩小/左移/咬合"全是同一循环 + CSS 变换,**无需额外渲染**。

| ID | 资产 | 规格建议 | 服务需求点 | 备注 |
|---|---|---|---|---|
| **B-1** | `ball-intro` 入场序列 | 透明 PNG 序列,~60–90 帧,时长 1.2–2s,含 灭→不规则闪→渐亮 | HR-2 / HR-3 | 若改用 `ball-loop`+CSS 滤镜模拟闪烁,则本资产可省(取舍见下) |
| **B-2** | `ball-loop` 自转循环 | 透明 PNG 序列,严格**无缝** 360° 自转,~120 帧;@2x,建议 1024²~1440² | HR-3/4/6/7/8/9 | **全片工作马**;缩小/左移/咬合都靠它 + CSS |
| **B-3** | `ring-loop` 星环循环 | 透明,斜 30°,无缝旋转,与球分离渲染;与 B-2 同摄像机 | HR-5 / HR-6 | **必须独立**,否则 HR-6 星环无法独立变速 |

**B-1 取舍**:接触不良闪烁有两条实现——
- (a) Blender 直接渲入 `ball-intro`:亮灭由灯光动画烘死,质感最真,但闪烁节奏不可后期调;
- (b) 只出 `ball-loop`,前端用 GSAP `SteppedEase` + CSS `brightness/opacity` 模拟闪烁:节奏可调、少一个渲染,但发光碎片不随亮灭真实变化。
→ **建议先走 (b) 快速验证观感,不满意再补 (a)**。

## D. 明确**不是** Blender 资产(避免过度建模)

| 内容 | 归属 |
|---|---|
| 专辑封面 / 电影剧照 / 游戏封面 | **用户上传的 2D 内容**,非 Blender |
| 文摘文字 / 台词 | 排版(字体 + CSS) |
| 半圆凹槽、welcome 标题、三板块卡片、UI | DOM + CSS |
| text-roll / fade-up / revealer / 页面过渡 | GSAP(DESIGN_SPEC §5) |
| 光晕 / glow / 主色渐变 | CSS(可选叠加在渲染帧上) |

## E. 规格与约定(所有资产统一)

- **背景**:一律透明(Blender Film > Transparent)。
- **分辨率**:按最大展示尺寸出 @2x(retina);灯球 hero 建议 1024²–1440²。
- **无缝循环**:凡"持续旋转"资产(B-2/B-3/C-1/C-2)首尾帧必须可无缝衔接,否则 scroll 变速会跳帧。
- **帧数**:循环类 ~120 帧起,依最终滚动长度与顺滑度微调;入场类按时长×帧率。
- **交付格式**:优先 **sprite sheet(.webp)**;帧数多/体积大再用 webm-alpha(+ Safari HEVC-alpha 回退)。
- **命名**:`{asset-id}_{state}_{@2x}.{ext}`,如 `ball-loop_@2x.webp`、`ball-intro_seq/####.png`。
- **摄像机一致**:同一场景内需合成的资产(如 B-2 球 + B-3 星环)必须同摄像机、同分辨率、同中心,保证前端叠放对齐。

## F. 复用性结论

1. **主页灯球 = 全站 3D 资产的种子**。搭 M-1~M-5 主控的成本主要花在灯球上,之后 radar 的黑胶(C-2)、奖杯(C-3)等都是"换模型复用体系"的增量。
2. **主页动画本身极省渲染**:只需 B-1/B-2/B-3 三个产出,后续所有缩放/位移/咬合靠 CSS,不回 Blender。
3. **管线一次成型、处处适用**:「Blender 透明序列 → sprite/alpha 视频 → CSS 编排」对灯球、黑胶、奖杯完全一致。
4. **优先级**:先做 B-1~B-3 打通主页与管线 → 再按 C-2(音乐/黑胶,主板块+核心体验)→ C-1(品牌 motif,零成本)→ C-3/C-4/C-5 按需。
5. **风险控制**:预渲染的代价是"改样要回 Blender 重渲",故 M-1~M-5 要在第一次就把材质/打光/预设定稳,减少返工。
